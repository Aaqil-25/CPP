## Overview

The whole module is about **subtype polymorphism**. The single big idea that runs through all four exercises:

> A pointer/reference to a **base** class can point to a **derived** object. When a member function is declared `virtual`, calling it through the base pointer runs the **derived** version (decided at **runtime** = *dynamic dispatch*). Without `virtual`, the compiler picks the function based on the **static type** of the pointer (decided at **compile time** = *static dispatch*).

Every class is in **Orthodox Canonical Form (OCF)**: default constructor, copy constructor, copy-assignment operator, destructor. Every constructor/destructor prints a distinct message so the evaluator can watch object lifetimes in the terminal.

### The header dependency trick (forward declarations)

`AMateria` needs `ICharacter` (its `use` takes an `ICharacter&`), and `ICharacter` needs `AMateria` (its `equip` takes an `AMateria*`). That's a circular dependency. Solution: each header **forward-declares** the other class instead of including it.

```8:8:d:\42\CPP-main\cpp04\ex03\AMateria.hpp

```
```8:8:d:\42\CPP-main\cpp04\ex03\ICharacter.hpp

```

A forward declaration is enough when you only use the type as a **pointer or reference** (the compiler doesn't need the full definition yet). The `.cpp` files include the real headers.

## Quick answers to likely evaluation questions

- **Why virtual destructor?** So deleting a derived object through a base pointer runs the full destructor chain; otherwise the derived part leaks. Demonstrated in ex01/ex02.
- **Deep vs shallow copy?** Shallow copies the pointer (two owners → double free / shared state). Deep allocates a new object and copies contents. Shown with the Brain address comparison and the Character clone surviving the original's deletion.
- **What makes a class abstract?** At least one pure virtual (`= 0`) function → cannot be instantiated (ex02 `Animal`, ex03 `AMateria`).
- **What is an "interface" in C++98?** A class with only pure virtual functions and a virtual destructor (`ICharacter`, `IMateriaSource`).
- **Why forward declarations in ex03?** To break the circular include between `AMateria` and `ICharacter`; legal because they're only used by pointer/reference in the headers.
- **Where do unequipped materias go?** To the `floor` array, deleted in `~Character` — satisfies both "don't delete in unequip" and "no leaks."
